# Migrating an app to the Sustainable FSA style kit

The playbook for converting an existing Sustainable FSA dashboard into a kit
consumer, written for a session starting **fresh in the consumer's repo** with
no other context. Aimed squarely at the LFP eligibility dashboards, which are
the next three migrations.

Read order:

1. **this file** — the process,
2. **[HOUSE-STYLE.md](HOUSE-STYLE.md)** — the rules,
3. **your app's row in [CONSUMERS.md](CONSUMERS.md)** — per-app intel, including
   known defects to fix on the way through,
4. **`fsa-normal-grazing-period`** — the pilot, and the reference implementation
   of every convention here. When something in this file is ambiguous, the pilot
   is the answer.

Every bare path in this file (`snippets/…`, `tools/…`, `demo/`) lives in the
**style repo** — clone it as a sibling of the app
(`git clone git@github.com:sustainable-fsa/style.git`), or read the files on
GitHub. The current released version is in the kit's
[CHANGELOG](CHANGELOG.md) and its README quickstart; pin exactly that version.

## Understand what kind of work this is

**This is a port, not a restyle.** Today's dashboards are Quarto documents with
Observable JS cells: the map, the legend, the join, and the controls are all
generated by Quarto's runtime, and there is no `index.html` to reskin. What
comes out is a static single-page app that loads the kit by URL and owns its own
markup.

That changes the first step. There is no CSS block to diff, so the conflict
matrix runs against **behavior**: every control, every URL parameter, every
tooltip field, every color decision the dashboard makes today.

## Step 0 — fix the data before you fix the page

**For `fsa-lfp-eligibility-web`, this step is mandatory and comes before
everything else.** Its join key is built from FIPS state and county codes and
joined against FSA-coded geometry (CONSUMERS.md § its row; HOUSE-STYLE §7). Some
counties silently don't match, and a few match the wrong FSA office.

- Re-key to the **5-character FSA county string** (state FSA code + county FSA
  code), and keep it a string everywhere. `parseInt` on a county id is a
  review-blocker.
- Apply the **vintage rule** (dd17 ≤ 2014, dd22 ≥ 2015) — the dashboard
  currently draws every year on dd17.
- **Verify before and after**: counties drawn per program year, and the list of
  ids present in the data but absent from the geometry. Do this on the *existing*
  dashboard so the port cannot be blamed for, or hide, the correction. The
  difference is the bug you just fixed; write it into the migration commit
  message.

## The process

1. **Build a conflict matrix.** For every behavior the app and the kit both
   have — tokens, chrome, controls, URL params, tooltips, legends, keyboard
   handling, export — record app-behavior vs kit-behavior and classify:
   `IDENTICAL` (delete the app copy), `DRIFT` (decision needed), `KIT-NEW`
   (adoption decision), `APP-SPECIFIC` (keep, untouched). Be exhaustive — the
   matrix *is* the migration.
2. **Resolve every DRIFT / KIT-NEW with Kyle** using the three-way framework:
   **(1) adopt kit · (2) app overrides** (mark it `/* kit-override: <why> */`)
   **· (3) back-port to kit**. He expects to be asked; batch the questions
   (≈4 per round), each shaped like:
   > *Legend placement: dashboard puts it top-right, kit panel docks bottom-left.
   > Recommend adopt kit (the county card takes the right side on compact).
   > (1) adopt kit · (2) app overrides · (3) back-port top-right to kit?*

   Include a recommendation on every question. The precedents below are already
   settled — don't re-ask those. Pure-WCAG fixes and byte-identical deletions
   need no questions at all.
3. **Kit changes ship first.** Any option-3 back-ports land in the kit, are
   released per the [AGENTS.md](AGENTS.md) checklist, and only then does the app
   pin the new version path. **Never point an app at unreleased kit code** — and
   with pinned version paths you literally cannot, which is the point.
4. **Port** (technical steps below).
5. **Verify** (recipe below) — all of it, before any push.
6. **Deploy gate.** Check how the repo deploys before touching git: these repos
   publish GitHub Pages from `main`, so **pushing main IS a production deploy**.
   Present verification results and get an explicit OK first.
7. **Close out**: update the app's row in CONSUMERS.md (a commit in the kit
   repo), and put the full decision table in the app's migration commit message.

## Settled precedents — don't re-litigate

- **FSA string ids** for every county join; **vintage follows the program year**
  (dd17 ≤ 2014, dd22 ≥ 2015); geometry fetched at runtime from the boundary
  archives' Pages. (HOUSE-STYLE §7.)
- **No basemap.** The county composite on cream is the map. Rotation and pitch
  off.
- **Two themes**: light default, high-contrast first-class. There is no dark
  theme and one is not coming.
- **Tokens win** over any color the dashboard hard-codes, except data ramps
  (app-owned, HOUSE-STYLE §6, with contrast comments per §5.10).
- **`batlow` sequential, `romaO` cyclic, `Spectral` banned.** The pilot's
  pairing (romaO for start/end day-of-year, batlow for duration) is the house
  reference; a categorical eligibility scheme prints its class names.
- **UTC-only date math** for civil dates (see Gotchas).
- **URL is primary state**, precedence URL > localStorage > default,
  whitelist-validated, clean URL at all defaults, share copies `location.href`.
- **`sfsa-theme` is shared org-wide**; every other key is `sfsa-<app>-*` and is
  re-validated on read.
- **Page title** per the CONSUMERS.md table; `og:site_name` is
  `Sustainable FSA` alone.
- **Meta CSP on every page**, `viewport-fit=cover` in the viewport meta, skip
  link first in `<body>`, `<main id="main" tabindex="-1">` around the app
  surface.
- WCAG checklist items (live region, the sr summary + on-demand table twin, live
  `reducedMotion()` gates, removal of `outline: none`, touch targets, `?kbd=off`
  for single-char shortcuts, persisted-state re-validation) are **pre-authorized**
  — apply without asking.

## Technical steps

**Develop against root-absolute paths, release against versioned URLs.** Serve
the whole workspace (`python3 -m http.server 8000 -d …/sustainable-fsa`) and
write `/style/theme/sfsa-theme.css`, `/style/core/core.js` while you work: the
paths resolve the same locally and in production, and the boundary archives
resolve too. At release, rewrite `/style/` → `https://sustainable-fsa.com/style/vX.Y.Z/`
in one pass — except `vendor/`, which is pinned by **library** version and never
carries a kit version (`/style/vendor/maplibre-gl-5.18.0/…`).

**Head / markup** (`index.html`):

- Copy `snippets/head.html` and **keep its order**: metas → CSP → the inline
  anti-flash boot (`snippets/anti-flash.html`) → icons → font preload →
  MapLibre CSS → kit CSS. Then, at the **end of `<body>`**, the two classic UMD
  scripts followed by `<script type="module" src="app.js">` — the kit's map
  modules expect `window.maplibregl` and `window.topojson` to already exist,
  and a module script is deferred, so it runs after both.
- Meta CSP: everything is same-origin (README § Quickstart has the block). Add
  `worker-src blob:` and `img-src … data: blob:` — MapLibre needs both — and
  recompute the inline boot script's `sha256` **from your own page**.
- Skip link first in `<body>`; app surface in `<main id="main" tabindex="-1">`;
  the sr-only summary next to the map; the "View as table" button that opens the
  on-demand table dialog.
- The navbar is the banner lockup + brand block + `.controls`; the app title is
  usually the `<h1>` and carries `.brand-title` so the outline survives the
  responsive shed.

**Data payload:**

- Build a browser-shaped columnar JSON from the archive's canonical file, and
  **version it** (`fsa-ngp-web/1` is the pilot's). County ids stay strings with
  their leading zeros. Program years become a dense index. Ship it in the app
  repo next to `index.html`.
- Keep the archive CSV/parquet as the source of truth; the payload is a
  derivative and its build script belongs in the app repo.

**JS** — swap the Observable idioms for kit calls:

| The dashboard had | Use instead |
|---|---|
| `d3.json(...)` on a hard-coded topojson URL | the county module's loader (vintage-aware, cached, reports unmatched ids) |
| a hand-rolled `rowById` join with `padStart(5,"0")` | the county module's FSA-string join |
| `Inputs.select` / `Inputs.radio` | kit controls wired to URL state |
| an inline SVG legend | `ui/legend.js` (continuous, cyclic wheel, or categorical) |
| a `title`-attribute or d3 tooltip | the kit tooltip + `ui/card.js` for the persistent read |
| ad-hoc `localStorage` reads | the core module's throw-safe storage, `sfsa-<app>-*` |
| `new Date("2011-05-01")` arithmetic | the core module's UTC civil-date helpers |
| a screenshot or Observable download | `ui/export.js` (`?export=` convention) |
| prose in a Quarto cell | `ui/help.js` over markdown that ships in the repo |

## Gotchas

Each of these costs an afternoon the first time.

- **The CSP `sha256` is per-page, indentation included.** Never copy another
  app's hash. Hash the exact bytes of the first inline `<script>` element of
  **your own** `index.html`:
  ```sh
  python3 -c "
  import base64,hashlib,re
  h=open('index.html').read()
  s=re.search(r'<script>(.*?)</script>',h,re.S).group(1)
  print('sha256-'+base64.b64encode(hashlib.sha256(s.encode()).digest()).decode())"
  ```
  A CSP console error on load is the telltale; treat it as a hard failure, never
  as noise to filter.
- **MapLibre paints cannot read CSS custom properties.** `var(--accent)` in a
  paint is not a value the GL renderer understands. Resolve tokens with
  `getComputedStyle(document.documentElement).getPropertyValue('--x')` **at
  layer-add time and again on every theme change** — a theme toggle that only
  swaps `data-theme` leaves the map painted in the old palette.
- **`setData` wipes feature-state.** Hover halos and the selection ring live in
  `map.setFeatureState`, and re-pointing the source at another vintage silently
  drops all of it: the last hovered county keeps its halo forever. Call
  `removeFeatureState(source)` **before** `setData`, then re-apply. The kit's
  `swapVintage` encapsulates the whole sequence — use it rather than calling
  `setData` yourself.
- **`worker-src blob:` and `img-src data: blob:` are required.** MapLibre spawns
  its workers from blob URLs and moves glyph and sprite data through `data:` /
  `blob:` URLs. Miss either and the map is a blank cream rectangle with a
  console full of CSP violations.
- **`document.fonts.load()` per weight before any canvas `fillText`.** The
  variable Roboto is one file, but the canvas font matcher wants each weight
  loaded before it will use it — draw a 900 title before
  `await document.fonts.load('900 48px Roboto')` resolves and the export
  silently falls back to a system serif. Load every weight the export uses, then
  draw. The same applies to the banner: rasterizing it needs the patched SVG
  with intrinsic dimensions (HOUSE-STYLE §1).
- **Write the first-visit key AT OPEN, not at close.** Write it on close and
  anyone who navigates away without dismissing the modal sees it again every
  single visit. Deep links (a URL naming a county or a year) suppress the
  auto-open entirely.
- **UTC-only date math for civil dates.** A grazing period start of `05-01` is a
  *civil date* — it has no time zone and no instant. Parse with `Date.UTC(...)`,
  read with `getUTC*`, format with `Intl.DateTimeFormat(…, {timeZone:'UTC'})`.
  Local getters shift a date by a day for anyone west of UTC and the error is
  invisible in Mountain Time only for part of the year. This is the opposite of
  what a timestamped-observation app wants, and the reason the kit's date
  helpers are UTC-only rather than zone-aware: nothing in these archives is an
  instant.
- **Kit-owned is a per-selector fact, not a per-section one.** When you do delete
  CSS, diff the class names the app actually emits against the ones the kit
  actually styles. Deleting a section wholesale because "the kit owns this"
  reliably takes app-owned rules with it.
- **A blank county is two different facts.** "No polygon in this vintage" (the
  island territories are in neither archive) and "no reported value for this
  county-year" must not render identically. Both belong in the legend and in the
  sr summary.
- **Pages `max-age=600` only bites mutable paths.** Versioned kit URLs are
  immutable, so a stale cache is a correct cache. Your own `index.html` and data
  payload are not versioned — expect up to ten minutes of skew when verifying a
  deploy, and poll rather than concluding.

## Verification recipe (all before any push)

The consumer repos have **no CI** — every gate here is manual. Install the
tooling ephemerally and keep it out of git (`node_modules/`, `package.json`,
`package-lock.json` in `.gitignore`):

```sh
npm init -y && npm i --no-save playwright @axe-core/playwright
npx playwright install chromium
```

- `node --check app.js` · `npx --yes html-validate@9 index.html`.
- **Console clean in both themes**, with the CSP live. Any blocked resource or
  missed endpoint shows up here. A justified noise allowlist is fine; **never
  filter a CSP violation** — that is the check's entire purpose.
- **axe: 0 serious/critical** in light and high-contrast, at **1440px and
  390px**. A shed label is invisible to a desktop-only audit
  (HOUSE-STYLE §3). `tools/a11y-audit.mjs` in the kit is the model — copy it
  into the app repo untracked and point it at the app's page.
- **Data assertions, not screenshots**: counties drawn per program year for a
  sample of years across the vintage boundary (2013, 2014, 2015, 2016), ids in
  the data with no polygon, ids in the geometry with no data. Compare to the
  archive. This is the check that would have caught the `-web` join defect.
- **URL param matrix**: every param honored on load and re-emitted; defaults
  elided; deep links suppress the help modal; `?kbd=off` gates and sticks;
  `?export=` produces a PNG with the banner and the credit line rendered.
- **Vintage swap**: step across 2014 → 2015 with a county selected and confirm
  the selection ring and hover state are correct afterward (the feature-state
  trap).
- Compact viewport (390px): the county card docks, the search collapses, nothing
  overflows horizontally.
- Post-deploy: poll until a file new to this migration returns 200 on the live
  URL, then repeat the console + axe pass against production.

## Kit-deferred pieces (keep app-local; do NOT extract)

See [CONSUMERS.md](CONSUMERS.md) § Kit-deferred for the current list — the
month-wheel legend and the grazing-span chart as of v0.1.0. Leave the app's
versions in place, swapping only their internals onto kit helpers where trivial
(tokens, the live region, the export path). If a migration makes one converge
naturally, propose it as a kit MINOR — that is the intended path to absorption,
and the **admission rule (≥ 2 properties)** is what opens it.
